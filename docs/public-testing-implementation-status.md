# Public-testing completion status

September 30, 2026. This records the implementation against [the plan](public-testing-completion-plan.md). It is not a claim that the app is approved for public distribution.

## Implemented locally

- A deleted space disappears from the active selector after the confirmed deletion. Owner-requested cleanup can drain immediately, while the scheduled worker remains the fallback. Invite replacement is one batch, with owner checks and expiry inside the Firestore rule limit.
- The tour points to live controls instead of fabricated miniature examples. Its first-use account flag remains; replays are manual. New clay art covers the three onboarding cards, Couple and Other space types, Today rest, and Moments selfie. Transparent derivatives of the Family, Friends, and Organization references are retained alongside the originals. Sparse clay motifs and waves appear behind onboarding and all three app tabs.
- Optional profile photos work from the onboarding camera/gallery or Account Settings. The image is cropped, reduced, EXIF-stripped, and stored in the account's Firestore profile; reads require shared-space membership. A pending onboarding upload can retry after verification. Initials and colors remain deterministic when no photo exists.
- Space has the account settings gear, compact name field, owner rename action, icon tiles, and a single sheet handle in the changed sheets. The MapTiler pilot key is the plain `flutter run` default, with a Dart-define override. The mood write path calculates expiry at space-local midnight on the authenticated server, with a local UI expiry timer and gray question placeholder.
- FCM replaced OneSignal for optional transport. Devices register per signed-in account, rotate token, and remove the registered token on sign-out. The scheduled worker sends generic FCM messages after checking preferences, membership, and quiet hours; invalid tokens are pruned. Push taps open the account inbox, whose task/space actions recheck access. Firestore inbox activity remains independent of push.
- The Plus paywall describes unlimited retained, authorized task history. The deployed authenticated history gateway enforces today and the previous three space-local calendar dates for Basic; Plus paginates retained authorized history without an age cutoff. Completed task details are read-only. Store-provided localized prices are used when checkout is enabled.

## Deployed and checked

- Firebase Firestore rules for the changed profile, push-device, invite, mood, history, calendar-event, and space behavior were deployed to `stewardie`, along with the account-wide unread index. The focused Firestore emulator rules suite passed 18/18, including account/profile/device authorization and rejection of blind completed-task edits. Newly submitted indexes can require build time before the unread query works.
- `mood`, `task-access`, `media`, `space-actions`, and the updated `scheduled-work` Edge functions were deployed to Supabase project `ulexhxfxatzlobabitpr`. Unauthenticated requests to the two new functions returned 401. Authenticated two-account behavior has not been exercised on a device.
- Changed Edge routes passed Deno type checking. Nine focused history/delivery policy tests passed; the live `task-access` route returned 401 without authentication. The media deployment initially returned an internal 500; the reviewed API-bundler retry succeeded before rules deployment.
- Targeted Dart analysis of the changed app areas finished with no errors or warnings; info-level lints remain. No Android or iOS build, live push receipt, or physical-device test was run for this record.

## Open implementation and verification limits

- **RevenueCat:** Replacement Test Store products `stewardie_plus_monthly_499` (US$4.99/month) and `stewardie_plus_annual_3999` (US$39.99/year) were created, attached to `stewardie_plus`, and saved into the default monthly/annual offering. [Dashboard evidence](revenuecat-offering-sep30.png). Existing products were retained. Purchases remain explicitly gated; Test Store keys are excluded from release builds. Nonfounder tester purchase/restore/expiry/account-switch and live webhook/reconciliation tests still need an enrolled tester and native device. Real Play/App Store configurations remain unavailable.
- **History verification:** The UTC boundary gap is fixed through `task-access`, with membership and entitlement rechecks, bounded pages, stable cursors, and shared authorization for media/task links. Three focused tests cover Manila/extreme time zones, DST, inclusivity, Plus expiry, and unfinished work. Authenticated live pagination, downgrade, and cross-device history still need owner checks.
- **Notifications:** Atomic calendar edits/cancellation/arrivals and task declines/offers/material edits/arrivals now feed the worker. Join decisions, membership removal, deletion, and cleanup failures get private notices; failed cleanup can be retried from the inbox. Optional photo/reaction/mood activity is controlled per space, defaults off, and is derived from successful cloud records. Mood updates never push their content. See [coverage inventory](notification-coverage.md) for deliberate no-alert paths and limitations. Native push receipt, permission denial, token rotation, account switch, quiet hours, and taps still need physical-device checks; iOS needs APNs.
- **Media and UI:** Cross-device profile photo visibility, the new art at small/enlarged layouts, sheet insets, tour first-use behavior, map tiles, mood midnight/DST behavior, camera and Moments remain device checks. Firestore profile photos are a small-pilot storage approach; size/quotas should be monitored before a wide rollout.
- **Space operations:** Authenticated owner rename/deletion drain and invite create/redeem still need two-account verification. Cleanup must be checked for completed jobs and media deletion, not inferred from a successful enqueue. The owner has a private cleanup status/retry action; operator scripts remain available for investigation.
- **Public release:** Android signing/package identity, working external privacy/terms/deletion/support pages, operator moderation process, abuse/quotas review, policy declarations, and invited physical-device pilot remain gates. No Play developer account or real Play product configuration exists. This work did not enable billing, OneSignal Growth, or public publication.
