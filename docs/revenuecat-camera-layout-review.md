# Independent implementation review — September 24, 2026

Reviewed the working-tree changes against HEAD `ace8836`, including the new plan, verification document, and reconciliation function. Git does not identify the author of uncommitted changes; these are treated as the Gemini implementation supplied for review.

Verdict: changes requested. The existing Flutter suite passes, but subscription reconciliation and photo framing are not ready for sign-off or deployment. No application source was changed and no cloud operations were performed during this review.

## Findings

1. **P1 — Reconciliation reports success without saving entitlement state.** `supabase/functions/reconcile-subscription/index.ts:269` falls back to the caller's Firebase ID token. The account rules prohibit clients from writing these subscription fields. The function does not use the documented `FIREBASE_CLIENT_EMAIL` / `FIREBASE_PRIVATE_KEY` credentials to obtain a server access token; it reads a different static token variable. At lines 144–146, failed PATCH responses are merely logged, and 404 is ignored. The handler still returns success/Plus, so the paywall can celebrate activation while protected features remain Basic. A mocked 403 write reproduced a 200 success acknowledgement. Implement renewable server authentication, require successful persistence, and return a retryable failure when storage fails. Do not replace missing RevenueCat credentials with an inactive subscription: lines 157–166 can downgrade a valid non-founder account during misconfiguration.

2. **P1 — Webhook authentication fails open.** At `supabase/functions/reconcile-subscription/index.ts:220–224`, an absent webhook secret skips authentication entirely. Once gateway JWT checks are disabled for Firebase/custom authentication, an unauthenticated POST can trigger privileged reconciliation for a supplied UID. A local mocked request without Authorization reproduced a successful PATCH. Require the secret and valid authentication before processing; missing configuration must fail closed. The comment claiming delivery deduplication is also unsupported: no event-ID storage or concurrency protection exists.

3. **P1 — Test subscriptions are not restricted to the authorized founder.** `lib/features/subscription/revenuecat_service.dart:247–270` gates only on build configuration and initialization. The backend at `supabase/functions/reconcile-subscription/index.ts:263–267` grants Plus to any authenticated UID with an active RevenueCat entitlement, without checking the permitted test account or subscription environment. Founder detection only preserves an existing grant. Thus another account using the enabled development build can purchase a simulated subscription and receive protected Plus. Enforce the approved tester restriction on the trusted backend and separately model subscription versus founder state; `_isPlus` alone cannot prove that the founder's test subscription activated successfully.

4. **P1 — Late purchase/restore/reconciliation responses cross account boundaries.** `lib/features/subscription/revenuecat_service.dart:208–240`, `:265–273`, and `:328–340` update singleton state after awaits without rechecking the captured UID and epoch. Initialization has those guards, but these new paths do not use them. If account A's HTTP response arrives after sign-out or account B's sign-in, it overwrites the new session's subscription state. Purchase/restore also run outside the identity-change queue. Capture and revalidate the session around each awaited operation and reject stale results before updating state or emitting success. This is a client-state race; this review did not establish a server-side cross-account grant.

5. **P1 — Square framing does not crop the TV composition.** `lib/features/media/media_library.dart:124–138` uses Align size factors under the TV's tight constraints. This does not scale and clip the source pixels to the requested normalized rectangle. A rendered 400×200 test image had red outer quarters and a green central square. In a 300×200 container, both Original and Square left 22,500 red pixels visible; a correct central square removes those edges. Compute the crop using decoded image dimensions, render that source rectangle, and contain-fit the resulting composition. Retain the full bytes for viewing/export.

6. **P1 — Cloud sharing discards framing.** The new local model serialization in `lib/features/media/media_library.dart:269` is not connected to the shared-media path. `lib/online/cloud_media_library.dart:223` sends no framing field, `_decode` at line 100 creates attachments with the full-frame default, and the media gateway/database schema has no framing persistence. A successful upload replaces the locally framed attachment with the unframed remote result; other devices also receive the full frame. Carry and validate framing through multipart uploads, durable retries, storage, response decoding, and refresh. Add a round-trip test through the actual cloud adapter.

7. **P2 — Pending purchase handling catches the wrong exception type.** `lib/features/subscription/revenuecat_service.dart:285` catches the `PurchasesErrorCode` enum, but installed purchases_flutter 10.13.1 throws `PlatformException`. Pending payments fall through to generic error handling; cancellation relies on brittle message matching. Catch PlatformException and decode it with `PurchasesErrorHelper.getErrorCode`. The added test constructs result objects and never invokes this exception path. This matches the [official purchase integration](https://www.revenuecat.com/docs/getting-started/making-purchases).

8. **P2 — Today height changes target an unused route.** `lib/online/online_home.dart:502–545` changes the old `_today` implementation. Normal signed-in users receive `StewardieApp` from `lib/online/firebase_session.dart:177`; its Today route uses `lib/features/timeline/presentation/today_screen.dart`. That screen still has the original top clearance, 18px bottom padding, and 112px illustration. OnlineHome is used with `spaceOnly: true` for Space/setup. Apply the change to the active Today screen and measure it there; the claimed reduction currently does not reach the normal app.

9. **P2 — Camera geometry assumes portrait even in landscape.** `lib/features/media/camera_screen.dart:185–199` always uses preview height/width and forces the inner CameraPreview into that box. The installed camera package selects its aspect ratio based on device/locked orientation. The new outer tight constraints defeat that landscape geometry. Capture framing at lines 121–139 likewise always swaps preview dimensions instead of using the orientation-normalized saved image. Use orientation-aware preview geometry and derive persisted framing from the processed capture. Capture orientation locking is still absent. Native rotation testing remains necessary.

10. **P2 — Free framing is a fixed inset, not an editor.** `lib/features/media/photo_composer.dart:208–216` always selects a centered 90% rectangle. There are no handles or controls to choose another proportion, and the specified 9:16 and 16:9 presets are missing. Implement the promised framing choices or explicitly agree a reduced scope before presenting this as completed.

11. **P2 — Boundary crop input throws during deserialization.** `lib/features/media/media_library.dart:58–61` clamps x/y up to 1.0, then calls `clamp(0.01, 1.0 - validX)`. At x=1 (or x>0.99), the lower bound exceeds the upper bound. A direct test with `{'x': 1.0, 'y': 0.0}` throws ArgumentError. Validate finite, positive, in-bounds rectangles or safely default invalid records; do not let a malformed crop prevent the library from loading.

## Deployment and remaining validation

- `supabase/config.toml` only configures custom Firebase-token handling for `media`. The new function needs a corresponding deployment configuration for Firebase JWTs/webhooks; otherwise default Supabase JWT verification can reject requests before this handler runs. Confirm this after fixing fail-open webhook handling. See [Supabase function configuration](https://supabase.com/docs/guides/functions/function-configuration).
- No foreground subscription refresh was added. Local expiry is evaluated only when the account document emits; Space's plan label still reads raw `tier`. Rules/media checks now compare timestamp expiry, but missing expiry still grants Plus for a non-founder `tier=plus`. Define and validate that legacy/null state explicitly.
- No live RevenueCat catalog, prices, native purchase/restore, two-device flow, refund, webhook retry/order, or deployed Firebase/Supabase state was verified. The new verification document must distinguish these from completed work. The plan still says “proposed; awaiting approval,” which conflicts with its implementation record and needs an accurate status.
- The Space hero uses name length and a capped text multiplier to estimate height rather than measuring layout. Existing fixture layout tests do not establish the new authenticated Space header's long-name and enlarged-text behavior. This remains a validation gap, not a reproduced overflow finding.
