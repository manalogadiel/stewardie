# Stewardie project guidance

Read README.md and the relevant documents in docs/ before implementation. Treat confirmed decisions separately from proposals and launch gates. The subscription plan v1 governs tier boundaries and quotas; the UI plan governs visual tokens and navigation.

For UI work, read .agents/skills/soft-pop-ui/SKILL.md and its project-context reference. Preserve Flutter, the Soft Pop pastel clay direction, and Today / Moments / Space navigation unless the user requests a change.

Plus belongs to an individual account across authorized spaces. It does not upgrade other members or grant roles/private access. Basic users must retain access to unfinished tasks and shared task completion.

The repository contains a local Flutter demo alongside the plans. See docs/demo-foundation.md for implemented scope and verification limits. Distinguish demo data from real authentication, synchronization, payments, media, and location behavior. Do not claim verification without running the relevant checks.

Preserve existing work and plans during scaffolding. Approval to build locally is not approval to enable paid cloud services or publish. Keep project decisions in these repository documents rather than editing historical Codex output copies.
